Provider-neutral supervisor · Beads-governed

Provider exhaustion should not strand the work.

One Bead, one worktree, one branch, one gate record, one review. When a provider hits a quota wall mid-run, the supervisor hands the identical state to the next one and keeps going — and it still stops at a review-clean PR for a person to merge.

Topology

One state, three destinations

Beads holds the durable task record. The supervisor is provider-neutral: it owns routing, evidence, and the stopping rules, so no single conversation owns the run.

provider routing
isolated worktree → gates → multi-vendor review
checkpoint ledger
resume and status, rebuildable from Bead comments alone
human handoff
a review-clean PR, and the merge stays with a person

Procedure

Workflow

Six commands, run in order the first time. Every one of them returns structured JSON.

  1. 01 relay setup --adapter example-app Writes local state under .agents/agent-relay/, creates the ignored .resources/ cache, and syncs role bundles into the providers you already have installed.
  2. 02 relay doctor --json Checks manifests, roles, adapters, local state, and the project-local Beads store.
  3. 03 relay plan <bead-id> Recovers the Bead and project law, hashes the spec, and pauses for approval on the risk classes that call for it.
  4. 04 relay run <bead-id> Executes one owned workstream inside its own worktree, reruns the gates, and hands off to the next provider on quota, auth, or service failures.
  5. 05 relay review <bead-id> Scope-locked review over the exact diff artifact, by at least two distinct vendors for non-documentation work.
  6. 06 relay resume <bead-id> Reattaches after any interruption, from the local ledger or from Bead comments when the ledger is gone.

Contacts

Five ways a run can end

The exit class is the contract. Scripts can branch on it, and a person always knows whether the run needs them.

Stable exit classes and process exit codes
Exit class Code Meaning
success 0 The phase finished with gate and review evidence behind it.
human-action-required 10 An approval, a human-only gate, or missing delivery config stopped the run.
provider-quorum-unavailable 11 No remaining provider or reviewer pool satisfies the vendor policy.
project-misconfigured 12 Adapter, guidance files, or the Beads store are not in order.
unrecoverable-run-state 13 Run state cannot be trusted. The worktree is preserved for inspection.

Containment

Safety model

Every rule here fails closed. When the supervisor cannot prove a boundary held, it stops instead of delivering.

  • single writer Workers run bd --readonly. The supervisor is the only process that writes Beads.
  • project store The store is the repository's own .beads/ directory, git-ignored by default and never writable by a worker.
  • isolation Workers run in their own worktree with a declared read-only mount set and a synthetic writable HOME. Never the main checkout.
  • no drift Blanket staging, force-push, remote mutation, protected-path edits, and attribution in team-facing text are all rejected.
  • kept evidence Dirty or partially committed worktrees are preserved for inspection, never deleted on your behalf.
  • human merge Delivery stops at a review-clean PR. Without delivery configured, review pauses and says exactly what is missing.

Cache

Reference resources

.resources/ at the repository root is where agents keep external documentation instead of refetching it, guessing at it, or committing it.

  • ignored Git-ignored here, and relay setup adds it to local exclude state in the target project.
  • sourced One topic per subdirectory with a SOURCE.md recording the origin URL and the fetch date.
  • invisible Excluded from snapshots, diffs, review bundles, privacy scans, and link checks, so it cannot reach a PR.
  • read-only Mounted read-only for workers as AGENT_RELAY_RESOURCES_DIR. Project law always outranks anything cached in it.

Install

Setup

Version 0.1.0 is a local CLI and plugin package. There is no service to run and no account to create.

$ node scripts/sync-roles.mjs

# in the project you want to drive

$ bd init --quiet

$ relay setup --adapter example-app

$ relay doctor --json

Claude loads the plugin from .claude-plugin/, Codex from .codex-plugin/, and agy imports the same generated roles from .agents/agents/. Repo-local marketplace entries resolve through plugins/agent-relay.
